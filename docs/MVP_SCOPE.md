# MVP_SCOPE.md

## Цель MVP

Сделать первую рабочую версию системы, которой можно реально пользоваться для сопровождения нескольких клиентских сайтов.

MVP должен помогать разработчику:

* видеть проекты в одном месте;
* понимать, какой проект требует внимания;
* получать базовую техническую информацию;
* безопасно давать клиенту доступ к контенту;
* видеть историю изменений.

## Что входит в MVP

### 1. Projects

Возможность:

* создавать проект;
* редактировать его данные;
* подключать интеграции;
* хранить статус проекта.

### 2. Multi-project dashboard

Общий экран со всеми проектами.

Минимально показывать:

* название проекта;
* текущий health status из `project_health`;
* наличие проблем;
* последний успешный check;
* последний deploy;
* количество критических ошибок.

Основная задача экрана:

> Показать, какие проекты требуют внимания прямо сейчас.

### 3. Project Health

Минимальные проверки:

* HTTP availability;
* SSL;
* Deployment;
* Critical errors;
* Integration freshness.

Project Health и Integration Health разделены. Ошибка доступа к отдельному provider не
означает автоматически, что клиентский сайт недоступен.

### 4. Client CMS

Клиент может изменять только разрешённый контент.

Контент Client CMS хранится в Platform Database, которая является canonical source.
Существующий сайт получает данные через `CMS Contract v1`.

Базовые возможности:

* редактирование текста;
* редактирование числовых значений;
* загрузка и замена изображений;
* включение/выключение элементов;
* сортировка;
* создание и удаление разрешённых сущностей.

### 5. Developer Control Panel

Для каждого проекта разработчик видит:

* Overview;
* Content;
* Health;
* Deployments;
* Errors;
* Storage;
* Users;
* Integrations;
* Audit.

Не все разделы обязаны иметь сложный функционал в первой версии.

### 6. Roles / Permissions

Минимальные роли:

* CLIENT;
* DEVELOPER.

Ограничения должны работать:

* в интерфейсе;
* на сервере;
* на уровне базы данных.

### 7. Integrations

В обязательном порядке:

* GitHub;
* Vercel;
* Sentry.

Supabase подключается по возможности. PostHog поддерживается архитектурно, но остаётся
optional / later и не является блокером MVP.

### 8. Audit Core and Audit UI

Audit Core обязателен для security-sensitive действий и реализуется до Projects и CMS.
Страница Audit UI может появиться позже.

Фиксировать:

* пользователя;
* действие;
* проект;
* сущность;
* время.

## Приоритет MVP

Функции приоритизируются в таком порядке:

1. Authentication
2. Authorization + RLS
3. Audit Core
4. Projects
5. Client CMS
6. Media
7. Project Health
8. Integration Framework and required providers
9. Multi-project dashboard
10. Audit UI
11. CMS Contract v1

## Главное правило MVP

Если функция не:

* сокращает время обслуживания;
* уменьшает количество ручных действий;
* снижает риск ошибки;
* помогает быстрее понять состояние проекта;

она не входит в первую версию.
