# NON_GOALS.md

## Что мы сознательно не делаем в первой версии

### Создание сайтов

Продукт не:

* генерирует сайты;
* создаёт лендинги;
* содержит visual builder;
* заменяет Webflow;
* заменяет Framer;
* создаёт проекты с нуля.

Система начинает работать с уже существующим сайтом.

Это не означает подключение любого существующего сайта за несколько минут. В MVP сайт
подключается после того, как его управляемый бизнес-контент переведён на стабильный
`CMS Contract v1`, через небольшую одноразовую интеграцию. Дизайн сайта не меняется.

### AI

В MVP нет:

* AI-агента;
* автоматических AI-действий;
* AI-диагностики;
* AI-генерации контента;
* AI-управления инфраструктурой.

К AI можно вернуться позже, если появятся конкретные повторяемые задачи.

### Инфраструктура

Мы не создаём:

* собственный Git hosting;
* собственный deployment platform;
* собственную БД;
* собственный error tracker;
* собственную analytics platform;
* собственный CDN;
* собственный object storage.

Используем интеграции с существующими сервисами.

### SaaS-функции

На первом этапе не делаем:

* billing;
* подписки;
* тарифы;
* invoices;
* marketplace;
* partner program.

### Agency-функции

На первом этапе не делаем:

* сложные команды;
* десятки ролей;
* white-label;
* custom domains для панели;
* reseller model;
* отдельные agency workspaces.

### Универсальность

MVP не обязан:

* поддерживать все фреймворки;
* поддерживать все cloud providers;
* работать с любой CMS;
* покрывать все возможные типы сайтов.

Первая версия может быть opinionated и поддерживать ограниченный стек.

Не строим универсальный sync-engine между несколькими CMS, Supabase клиента и Platform DB.

## Основной принцип

Мы не строим платформу «для всего веба».

Мы строим инструмент для удобного сопровождения нескольких клиентских сайтов.
