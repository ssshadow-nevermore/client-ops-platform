# SUCCESS_CRITERIA.md

## Цель

Определить, когда первую версию можно считать реально полезной.

## Главный критерий

Разработчик должен использовать систему как основную точку входа для сопровождения клиентских проектов.

Если при проверке состояния сайтов он по-прежнему первым делом открывает пять разных сервисов, продукт ещё не решает задачу достаточно хорошо.

## Критерии успеха

### 1. Быстрый обзор проектов

Разработчик может за 1–2 минуты:

* увидеть все активные проекты;
* понять, какие из них требуют внимания;
* увидеть причину проблемы.

### 2. Меньше ручных проверок

Для базовой диагностики не требуется вручную открывать каждый сайт и каждую внешнюю панель.

### 3. Раннее обнаружение проблем

Система должна помогать обнаруживать базовые проблемы до того, как о них сообщает клиент.

### 4. Самостоятельность клиента

Клиент может выполнять типовые контентные изменения самостоятельно:

* текст;
* цена;
* изображение;
* статус;
* другой разрешённый контент.

При этом он не может повредить техническую часть проекта.

### 5. Контроль изменений

Разработчик может понять:

* кто изменил данные;
* когда;
* в каком проекте;
* что именно было изменено.

### 6. Масштабирование

После подключения нескольких проектов система не должна становиться заметно сложнее в использовании.

Добавление нового проекта должно увеличивать объём данных, но не хаос.

## Dogfooding-критерий

После нескольких недель собственного использования должен появиться эффект:

> Без этой системы сопровождать проекты заметно менее удобно.

Если такого эффекта нет, нужно пересмотреть продуктовую ценность.

## Что считаем хорошим ранним результатом

Первая версия успешна, если:

* подключено минимум 3 реальных проекта;
* система используется регулярно;
* разработчик действительно смотрит project health;
* хотя бы часть клиентских изменений проходит без участия разработчика;
* количество ручных проверок уменьшается;
* появляются конкретные примеры сэкономленного времени или предотвращённых проблем.

## Что НЕ считаем успехом

Не являются достаточными критериями:

* красивый интерфейс;
* большое количество функций;
* технически сложная архитектура;
* большое количество интеграций;
* положительная реакция людей, которые продуктом не пользовались.

Главный показатель — практическая польза при реальном сопровождении сайтов.
